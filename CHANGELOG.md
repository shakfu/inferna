# CHANGELOG

All notable project-wide changes will be documented in this file. Note that each subproject has its own CHANGELOG.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/) and [Commons Changelog](https://common-changelog.org). This project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## Types of Changes

- Added: for new features.

- Changed: for changes in existing functionality.

- Deprecated: for soon-to-be removed features.

- Removed: for now removed features.

- Fixed: for any bug fixes.

- Security: in case of vulnerabilities.

## [0.1.10]

### Added

- **`LlamaModelParams.load_mode`** -- exposes upstream's new `enum llama_load_mode`, together with the `LLAMA_LOAD_MODE_AUTO` / `NONE` / `MMAP` / `MLOCK` / `MMAP_MLOCK` / `DIRECT_IO` constants on the `inferna.llama.llama_cpp` facade.

- **`SDImageGenParams.ref_image_args`** -- exposes upstream's new `sd_img_gen_params_t.ref_image_args` key=value passthrough (`preset`, `resize_before_vae`, `ref_index_mode`, `vlm_max_size`, ...).

- **Web UI asset tests** -- `tests/test_mserver_embedded.py::TestWebUIAssets` (10 cases) covers the vendored snapshot and the four routes that serve it: assets present and valid gzip, each route returning the right bytes and MIME type, cache-busting query strings routing correctly, and the `serve_webui=False` gate returning 404. The snapshot is committed rather than built, so nothing previously would have caught it going missing or drifting away from those routes. One case asserts `index.html` references `./bundle.js` / `./bundle.css` and not `_app/immutable`, so pinning `LLAMACPP_WEBUI_VERSION` past `b9611` without porting the server to the new layout fails a test instead of shipping a broken UI.

- **Load-mode and reference-image tests** -- `test_params.py` asserts the `load_mode` enum and its boolean view stay consistent in both directions; `test_sd.py` asserts `ref_image_args` defaults, passthrough, and that the legacy booleans round-trip without clobbering caller-supplied args.

### Changed

- **llama.cpp sync to `b10369`** -- bumped `LLAMACPP_VERSION` in `scripts/manage.py` (`b9979` -> `b10369`). Three upstream API breaks were absorbed:

  - `llama_model_params` replaced the `use_mmap` / `use_mlock` / `use_direct_io` booleans with a single `load_mode` enum. The three booleans are retained on `LlamaModelParams` as a compatibility view that projects onto the enum, so existing Python code keeps working; `use_mmap` still reads `True` by default because the default mode is `AUTO`. Because the enum can only encode mmap and mlock together, `use_direct_io = True` now clears mmap/mlock, and vice versa.

  - `llama_sampler_init_penalties` gained a leading `n_vocab` argument (used by the GPU-offloaded sampling path). `LlamaSampler.add_penalties` takes it as its first argument, and the four in-tree call sites pass the model's vocabulary size. Callers outside the tree must add the argument; passing `0` disables the GPU sampling path's penalty stage rather than failing loudly, so pass the real vocabulary size.

  - `llama_sampler_init_dry` dropped its `n_ctx_train` argument; `LlamaSampler.add_dry` drops it too.

- **web UI snapshot refreshed to `b9611`** -- bumped `LLAMACPP_WEBUI_VERSION` in `scripts/manage.py` (`b9351` -> `b9611`) and re-fetched the committed snapshot under `src/inferna/llama/server/assets/webui/` (checksums verified against the bucket). The pin stays well behind `LLAMACPP_VERSION` on purpose: `b9611` is the newest build the fetcher can consume. The bucket still publishes the flat `bundle.js` / `bundle.css` pair through `b9620`, but from `b9616` the generated `index.html` references content-hashed SvelteKit output (`_app/immutable/bundle.<hash>.js`), and past `b9620` the flat files are gone entirely -- so bumping to a current build would fail the fetch outright rather than degrade. The UI's server contract is unchanged across the gap (`/props`, `/slots`, `/v1/models`, `/v1/chat/completions`, `/models/{load,unload}`), so the older snapshot is behind on UI fixes, not broken. Adopting the new layout is tracked as separate work; the constraint is documented at the pin. Adds ~0.9 MB to the wheel (`bundle.js.gz` 1.5 MB -> 2.37 MB).

- **whisper.cpp sync to `v1.9.2`** -- bumped `WHISPERCPP_VERSION` in `scripts/manage.py` (`v1.9.1` -> `v1.9.2`). No changes on the wrapped API.

- **stable-diffusion.cpp sync to `master-817-bcc7e29`** -- bumped `SDCPP_VERSION` in `scripts/manage.py` (`master-775-b5d8120` -> `master-817-bcc7e29`). Upstream removed the `auto_resize_ref_image` and `increase_ref_index` booleans from `sd_img_gen_params_t` in favour of the `ref_image_args` string. Both remain available on `SDImageGenParams` and are composed into `ref_image_args` (as `resize_before_vae=0` and `ref_index_mode=increase`) the same way the upstream CLI does, so they do not clobber caller-supplied args.

### Fixed

- **`LlamaSampler.add_penalties` rejected keyword arguments** -- the binding declared no parameter names, so the keyword call in `ConstrainedAgent` (`penalty_last_n=`, `penalty_repeat=`, ...) raised `TypeError` whenever a constrained agent was configured with `repeat_penalty != 1.0`. The parameters are now named (`n_vocab`, `penalty_last_n`, `penalty_repeat`, `penalty_freq`, `penalty_present`).

### Fixed

### Added

New `_llama_native.cpp` bindings exposed during the bump: (1) `LlamaModelParams.kv_overrides` (list of `LlamaModelKvOverride`) and `LlamaModelParams.tensor_buft_overrides` (list of `LlamaModelTensorBuftOverride`), each backed by an owned vector that appends the loader's empty-key / `{nullptr, nullptr}` terminator; `LlamaModelTensorBuftOverride.buft` now takes a buffer-type *name* (e.g. `"CPU"`, `"Metal"`) resolved against the registered ggml backends at assignment time via a new `resolve_buft_by_name()` helper that throws listing the available names on a miss. (2) `LlamaModelQuantizeParams.imatrix` -- importance-matrix data as `{tensor_name: [float, ...]}`, owned storage with a `name==nullptr` terminated array, improving low-bit (IQ*/Q*_K) quantization quality. (3) Module-level `llama_model_quantize(fname_inp, fname_out, params)` (also re-exported on the `llama_cpp.py` facade), releasing the GIL for the long native call and raising `RuntimeError` on a nonzero return. (4) Three new sampler chain methods: `add_top_n_sigma(n)`, `add_dry(vocab, n_ctx_train, dry_multiplier, dry_base, dry_allowed_length, dry_penalty_last_n, seq_breakers)`, and `add_adaptive_p(target, decay, seed)`. (5) Four `LLAMA_KV_OVERRIDE_TYPE_*` enum constants (`INT`/`FLOAT`/`BOOL`/`STR`) exported from `_llama_native_enums.cpp` and re-exported on the facade.

- **stable-diffusion.cpp sync to `master-709-92a3b73`: new params, enums, and bindings** -- bumped `SDCPP_VERSION` in `scripts/manage.py` (`master-672-1f9ee88` -> `master-709-92a3b73`). New `SDContextParams` path fields: `uncond_diffusion_model_path`, `embeddings_connectors_path`, `audio_vae_path`, `pulid_weights_path`, and `rpc_servers`; plus `vae_format` (int, `VaeFormat`) and `stream_layers` (bool, residency+prefetch streaming, needs `max_vram`). New `SDImageGenParams` PuLID identity-conditioning fields `pulid_id_embedding_path` / `pulid_id_weight`. Two new facade `IntEnum`s -- `VaeFormat` (`AUTO`/`FLUX`/`SD3`/`FLUX2`/`COUNT`) and `CancelMode` (`ALL`/`NEW_LATENTS`/`RESET`) -- plus a large batch of new `SDType` members (`IQ2_XXS`, `IQ2_XS`, `IQ3_XXS`, `IQ1_S`, `IQ4_NL`, `IQ3_S`, `IQ2_S`, `IQ4_XS`, `I8`, `I16`, `I32`, `I64`, `F64`, `IQ1_M`, `TQ1_0`, `TQ2_0`, `MXFP4`, `NVFP4`, `Q1_0`). New `SDContext.cancel(mode=CancelMode.ALL)` method (calls `sd_cancel_generation` from another thread while `generate_*` runs with the GIL released). `generate_video` gained `fps` and per-call `loras` (list of `{path, multiplier?, is_high_noise?}` dicts) arguments, plumbed through both the native binding and the `stable_diffusion.py` facade. `sd/__init__.py` re-exports `VaeFormat` and `CancelMode`.

- **whisper.cpp DTW alignment and VAD bindings** -- new `WhisperContextParams` properties `dtw_aheads_preset` (alignment-head preset; `dtw_token_timestamps` has no effect without a preset matching the model), `dtw_n_top`, and `dtw_mem_size`; plus `WhisperFullParams.vad_params` (read/write the embedded `whisper_vad_params`, held by value and exposed as a `WhisperVadParams`).

- **`scripts/audit_wheel.py`: built-wheel external-dependency auditor** -- new script that walks every `*.so*` (Linux: `readelf -d`) or `*.dylib`/`*.so` (macOS: `otool -L`) inside a built wheel, collects DT_NEEDED entries / install_names, and verifies each is one of (a) bundled by auditwheel (NEEDED matches the `-<8hex>.so` hash-rename pattern) or by delocate (install_name starts with `@loader_path`/`@rpath`/`@executable_path`), (b) on the platform baseline (manylinux_2_28+ allowlist on Linux; `/usr/lib/` and `/System/` on macOS), or (c) matched by `WHEEL_REPAIR_EXCLUDES_LINUX[<backend>]` / `WHEEL_REPAIR_EXCLUDES_DARWIN[<backend>]` in `scripts/manage.py` (fnmatch globs honored on Linux for entries like `libmkl_*.so*`; delocate-style substring match on macOS). Anything outside all three is reported with the exact `.so` file(s) referencing it. Backend and platform are auto-detected from the wheel filename (`<pkg>_<backend>-<version>-...manylinux_*` etc.); `--backend` / `--platform` override. Exit 0 on clean, 1 on findings, 2 on tooling/usage errors. Windows wheels return a "not implemented" stub. Wired into all seven `.github/workflows/_gpu-build-*.yml` reusables between "List built wheels" and "Upload wheels" so audit failures abort the job before a bad wheel is uploaded as an artifact; the audit-then-upload ordering means a vendor-SDK soname bump (e.g. `libcudart.so.12 -> 13`) that's not yet in the exclude list fails the build instead of producing a bloated/broken wheel.

- **Three additional SYCL Linux wheel-repair excludes** -- `libmkl_*.so*` (Intel MKL: 4 distinct `libmkl_*` libs appear in DT_NEEDED of `libggml-sycl-*.so`; the glob covers them version-independently), `libiomp5.so` (Intel LLVM-OpenMP runtime; pulled in by MKL, incompatible with `libgomp` in the same process), and `libirng.so` (Intel DPC++ random-number runtime; appears in DT_NEEDED of every SYCL-linked binary, not the "defensive only" I'd initially characterized it as) added to `WHEEL_REPAIR_EXCLUDES_LINUX["sycl"]` in `scripts/manage.py`. Empirically verified against `~/projects/personal/cyllama/dist/cyllama_sycl-*.whl`: every entry is load-bearing. Without them auditwheel would bundle ~500 MB of MKL plus the Intel OpenMP runtime, producing a wheel that conflicts with the user's installed oneAPI.

- **`scripts/release_notes.py` wired into the three release-uploading workflows** -- `.github/workflows/build-cibw-abi3.yml`, `build-gpu-wheels.yml`, and `build-gpu-wheels-abi3.yml` now extract the version's CHANGELOG section into `release-notes.md` via `python3 scripts/release_notes.py "${VERSION}" --output release-notes.md` and attach it to the GitHub release via `gh release create --notes-file release-notes.md`. The script falls back to `[Unreleased]` when the version-named heading is missing (with a stderr warning), and exits 2 writing no output when neither section exists; the workflow's `NOTES_ARGS=()` array stays empty in that case, degrading gracefully to a notes-less release. Already-existing releases fall through to `gh release edit --notes-file` so notes can be populated on a second run.

### Changed

- **stable-diffusion.cpp CPU-offload toggles replaced with backend-assignment specs** -- upstream `master-709` dropped the dedicated `sd_ctx_params_t` fields `vae_decode_only`, `free_params_immediately`, `offload_params_to_cpu`, `keep_clip_on_cpu`, `keep_vae_on_cpu`, and `keep_control_net_on_cpu`, replacing low-VRAM control with backend-assignment strings. `SDContextParams.max_vram` changed from `float` to a string spec ("" = disabled). A new `SDContextParams.apply_cpu_offload(*, offload_params=False, clip_on_cpu=False, vae_on_cpu=False, control_net_on_cpu=False)` helper translates the old toggles into `backend` (`te=cpu` / `vae=cpu` / `controlnet=cpu`) and `params_backend` (`*=cpu`) prepends, mirroring the upstream CLI. The `text_to_images` convenience function, the `sd/__main__.py` CLI, and the img2img/inpaint paths were migrated to the helper; img2img/inpaint no longer set `vae_decode_only=False` (upstream now always loads the full VAE). The `Upscaler` constructor dropped its `offload_to_cpu` positional arg (`new_upscaler_ctx` no longer takes it); the Python `Upscaler` keeps the `offload_to_cpu` keyword and translates it to a `params_backend="*=cpu"` spec.

- **`mtmd_helper_bitmap_init_from_file` / `_from_buf` signature change** -- upstream `b9672` added a trailing `placeholder` bool and changed the return type to a struct carrying a `.bitmap` member. `_llama_native_mtmd.cpp` was updated to pass `/*placeholder=*/false` and dereference `.bitmap`. No Python-facing API change.

- **Per-backend wheel-repair exclude lists hoisted to module scope in `scripts/manage.py`** -- moved out of the body of `do_wheel_repair` and into module-level constants: `WHEEL_REPAIR_EXCLUDES_LINUX`, `WHEEL_REPAIR_EXCLUDES_DARWIN`, `WHEEL_REPAIR_DARWIN_BASE`, `WHEEL_REPAIR_WIN_INCLUDES`, `WHEEL_REPAIR_WIN_EXCLUDES`. Single source of truth shared by `do_wheel_repair` (which feeds them to auditwheel/delocate/delvewheel) and `scripts/audit_wheel.py` (which reads the same dicts to classify NEEDED entries). The function body now just references the constants; no behavioral change to the repair output.

- **`WheelBuilder.build_dynamic_wheel` delegates to `do_wheel_repair`** -- previously called bare `auditwheel repair --plat linux_{ARCH}` / `delocate-wheel` / `delvewheel repair` with zero excludes, which silently bundled vendor runtimes when the local build set `GGML_CUDA=1` / `GGML_SYCL=1` / etc. The legacy three-platform `if PLATFORM == ...` branches were replaced with a single `Application().do_wheel_repair(Namespace(backend=infer_wheel_backend(), wheel=dist, dest_dir=wheels))` call. A new module-level `infer_wheel_backend()` helper maps `GGML_*` env vars to the backend tag using the priority order `CUDA > HIP > SYCL > Vulkan > OpenCL > Metal > CPU` (GPU SDKs before Metal so a SYCL cross-build on macOS isn't misclassified as Metal). `build_static_wheel` was untouched; it doesn't invoke any repair tool.

- **`pyproject.toml` Linux and Windows `repair-wheel-command` delegate to `manage.py wheel_repair`** -- bare `auditwheel repair -w {dest_dir} {wheel}` (Linux) and `delvewheel repair -w {dest_dir} {wheel}` (Windows) replaced with `python {project}/scripts/manage.py wheel_repair --backend cpu --dest-dir {dest_dir} {wheel}`. Behavior identical today because `WHEEL_REPAIR_EXCLUDES_LINUX["cpu"]` and `WHEEL_REPAIR_WIN_EXCLUDES` have no `"cpu"` entry; consolidates the surface so any future baseline-CPU exclude (e.g. `libssl`/`libcrypto` on Linux to mirror macOS) lands in one place. **macOS deliberately kept on the bare `delocate-wheel` command** because that path passes `--require-archs {delocate_archs}` -- a delocate-only safety check that errors if the repaired wheel's binaries don't match cibuildwheel's expected archs -- which `do_wheel_repair` does not expose. The bare command's `--exclude libssl --exclude libcrypto` flags are now annotated as mirroring `WHEEL_REPAIR_DARWIN_BASE` so the two must be kept in sync.

- **`do_fix_macos_vulkan_wheel` refactored into a CLI wrapper around `_fix_macos_vulkan_wheel(self, wheel_path: Path)`** -- the CLI handler now just resolves `args.wheel` as a directory (picks newest `*.whl`) or single file and delegates to the new private method. The internal call site in `do_wheel_repair` no longer constructs `argparse.Namespace(wheel=str(dist))` to satisfy the CLI signature; it iterates `dist.glob("*.whl")` and calls `self._fix_macos_vulkan_wheel(repaired)` directly per repaired wheel. Side benefit: fixes a silent bug where the prior newest .whl heuristic in the CLI path would miss other wheels in the same dir when `do_wheel_repair` produced more than one.

### Changed

- **Web UI is now a vendored snapshot fetched from the Hugging Face bucket** -- as of upstream `b9352`, llama.cpp removed the prebuilt server SPA from the source tree (`tools/server/public/` is gone; the UI is now a SvelteKit app in `tools/ui/` built via npm, downloaded from the `ggml-org/llama-ui` HF bucket, or pre-placed in `tools/ui/dist/`). inferna does not build the llama.cpp server, so `LlamaCppBuilder._copy_webui_assets()` in `scripts/manage.py` -- which used to copy + gzip the in-tree SPA at build time -- no longer has a source to read. The assets (`index.html`, `bundle.css`, `bundle.js`, `loading.html`) are now provisioned by a new `manage.py fetch_webui` subcommand that downloads the prebuilt UI from the HF bucket (`LlamaCppBuilder.fetch_webui_assets()`: tries the pinned `LLAMACPP_WEBUI_VERSION` then falls back to `latest`, verifies SHA256 checksums when published, gzips reproducibly with `mtime=0`), and the resulting `*.gz` snapshot plus a `VERSION` marker are **committed** into `src/inferna/llama/server/assets/webui/` (the `*.gz` gitignore was dropped). The build path now uses the committed snapshot offline -- no network or Node toolchain at wheel-build time -- and falls back to the legacy in-tree copy for older pins. The asset filenames and `embedded.py` serving routes are unchanged, so `serve_webui=True` works as before. The UI snapshot is pinned independently of `LLAMACPP_VERSION` (default `b9351`; the bucket does not publish every build, and `b9352` itself is absent) so a mismatch is auditable via the committed `VERSION` file.

- **Dropped the web UI brand-string rewrite** -- the previous `_copy_webui_assets()` rewrote `llama.cpp` -> `inferna` in `bundle.js` (the `APP_NAME` constant, the tab-title suffix, and the connection toast) and raised `RuntimeError` if a pattern was absent. The new SvelteKit bundle contains zero `llama.cpp` literals (the brand is a custom favicon plus internal `llama-ui` identifiers), so the rewrite is both impossible and moot; it was removed. The UI now ships upstream-as-is.

- Typed observation rendering for tool return values: new `render_observation(raw)` helper in `src/inferna/agents/react.py` is now the canonical conversion from a tool's raw return value to the string that lands on the `OBSERVATION` event `content`. - Per-tool timeouts via a new `Tool.timeout: Optional[float]` field plus `ToolTimeoutError` exception in `src/inferna/agents/tools.py`. Settable through `@tool(timeout=10.0)` or by writing `Tool.timeout` directly. When set, `ReActAgent._execute_tool_raw` runs the tool on a daemon thread, joins for the declared budget, and raises `ToolTimeoutError(tool_name, timeout)` if the worker exceeds it. Default is None (no enforcement). Implementation uses a raw `threading.Thread(daemon=True)` rather than `concurrent.futures.ThreadPoolExecutor` because the latter's `__exit__` blocks on worker completion -- which would re-introduce the hang we're trying to avoid; Python cannot safely kill threads, so a runaway tool keeps running until the interpreter exits, but the agent abandons the result and continues. Documented limitation: for hard resource limits (memory, file descriptors, network sockets), use out-of-process tools and let the OS enforce.

- `ReflectionLoop` -- Reflection/Reflexion pattern (Shinn et al., 2023) as a canned helper in `src/inferna/agents/composition.py`. - `plan_and_execute` -- Plan-and-Execute pattern (Wang et al., 2023) helper in `composition.py`. Takes a planner `AgentProtocol` (typically a `ConstrainedAgent` whose grammar forces a JSON list) and an executor; runs the planner once, parses its `answer` into a list of step strings via a pluggable `plan_parser` callable, then invokes the executor sequentially on each step. Returns `List[AgentResult]` -- one per executed step, potentially shorter than the plan if `stop_on_error=True` (the default) and a step failed. The default parser handles three JSON shapes (top-level list, `{"steps": [...]}`, `{"plan": [...]}`, `{"tasks": [...]}`) and falls back to newline-split with bullet/number-prefix stripping (regex `^\s*(?:[-*+]|\d+[\.\)])\s+` removed from each line); pass a custom callable to handle other plan formats. Planner-side failures (planner returns `success=False` or its output fails to parse) are surfaced as a single-element result list with the planner's failure context preserved, so callers can distinguish "the plan was bad" from "step 3 of 5 failed". 7 new tests covering happy-path sequential execution, the JSON-list and `{"steps"}` parser branches, the newline-fallback parser, stop-on-error vs continue-on-error semantics, failed-planner handling, and custom-parser injection.

- `SemanticMemory` -- long-term, RAG-backed, namespace-aware memory primitive in new module `src/inferna/agents/memory.py`. Bridges the `inferna.rag` subsystem to the agent layer as cross-session content-addressed recall: where `agents/session.py` handles short-term and episodic memory keyed by session ids, `SemanticMemory` handles "remember the user's preferences" across sessions via vector retrieval over arbitrary text fragments. New methods on `Workflow`: `@flow.node` and `@flow.node(name=..., timeout=...)` for registering Layer-C nodes with parameter-name-binding semantics; `@flow.route(after=...)` for conditional routers; `flow.add_node(fn)` non-decorator programmatic form (the existing `add_node(name, fn)` Layer-B signature is preserved -- overload dispatch is by first-arg type, string for Layer B vs callable for Layer C). Layer-C nodes have shapes like `def search(query: str) -> list[str]: ...`; the framework introspects the function at decoration time, builds a Layer-B wrapper that pulls each parameter from state by name, calls the user function, and stores the return value under the node's name. Dependency inference at compile time: for each Layer-C node, any parameter whose name matches another registered node creates a static edge from that node; parameters that don't match any node are recorded as workflow inputs and must be supplied via `run(**initial_state)` (the runtime raises a captured `WorkflowExecutionError` listing the missing inputs if any are absent). Self-referential parameters (a node whose param name matches its own name -- typically an accumulator with a seed value) are treated as workflow inputs rather than self-loops. Decoration order is irrelevant: a node decorated before its dependencies still wires correctly because edge inference runs at compile time. Layer-C and Layer-B definitions coexist on the same `Workflow` -- use Layer C for the common case, drop to Layer B for nodes that need multi-key state writes or hand-crafted state binding. `@flow.route` desugars to `add_conditional_edge(from_node, wrapped_router, edge_map=None)` where the wrapper binds params from state by name; routers can return either a target node name (string) or the `END` sentinel. New `Workflow.derived_state_schema` property synthesizes a `{state_key: type}` mapping from Layer-C metadata (node names + return annotations + input requirements) -- useful for debugging and as a foundation for Phase 4's typed-state generic. Return annotations are resolved via `typing.get_type_hints` so they work correctly under `from __future__ import annotations`. Layer-C nodes reject `*args`/`**kwargs` signatures with a clear `WorkflowDefinitionError` -- Layer C requires explicit named parameters because that's how the binding-by-name machinery works. 24 new tests covering the bare and parameterized decorator forms, name/timeout overrides, async-function decoration, dependency inference (linear, order-independent declaration, multiple-param fan-in, self-reference, missing-input failure), routes (basic dispatch, `END` termination, router-param input requirements), programmatic `add_node(fn)`, signature rejection, mixed-layer authoring, duplicate-name rejection across layers, and the derived schema with both inferred and explicit state shapes.

- DAG workflow orchestration (Phase 1: Layer B core) in new `src/inferna/agents/workflow.py`. Exports the canonical runtime model for DAG-based agent workflows: `Workflow`, `CompiledWorkflow`, `WorkflowResult`, three exception classes (`WorkflowDefinitionError`, `WorkflowExecutionError`, `WorkflowRoutingError`), and the `END` sentinel. The Layer-B API is the explicit StateGraph shape -- `add_node(name, fn, *, timeout=)`, `add_edge(from, to)`, `add_conditional_edge(from, router, edge_map=)`, `set_entry(name)`, `set_exit(name)`, then `compile()` to validate and `run()` / `arun()` to execute. State is a plain dict (or any `TypedDict` for type-checking); nodes return partial state updates that get shallow-merged into the running state. Static edges form a DAG validated by Kahn's algorithm at compile time (cycle detection raises `WorkflowDefinitionError`); conditional edges are resolved at runtime by router callbacks returning either a target node name (looked up in an optional `edge_map`) or the `END` sentinel to terminate the branch. Independent nodes at the same topological level run concurrently via `asyncio.gather`; sync node bodies are dispatched on `asyncio.to_thread` so they don't block the event loop, async bodies are awaited directly. Per-node `timeout=` integrates with `asyncio.wait_for` -- cleanly cancellable for async nodes; sync nodes match the documented `Tool.timeout` limitation (worker thread keeps running until process exit but the workflow abandons the result). User node exceptions are captured into `WorkflowResult(success=False, error=...)` rather than propagating; the `max_steps` cap (default 100) bounds conditional-edge cycles. Defensive state snapshots per node prevent accidental cross-node mutation. 35 tests in `tests/test_agents_workflow.py` covering builder validation (duplicate names, missing entry, unknown edge endpoints, cycle detection, mixed static-and-conditional outgoing edges), execution (linear pipelines, fan-out + fan-in synchronization, initial-state pass-through, empty/None returns, non-dict return failure), conditional routing (`edge_map`-based, direct-name-based, `END` termination, unknown-target failures, router-exception capture, edge_map miss), error capture (node exceptions skip downstream, max_steps cycle bound, async vs sync timeout semantics), and inspection (compiled levels match Kahn's output, defensive copies on read-only views). Phase 1 is the runtime foundation; Phase 2 (Layer C decorator sugar that compiles to Layer B), Phase 3 (streaming + visualization), Phase 4 (contracts + reducers + typed state), and Phase 5 (`AgentProtocol` compliance + sub-workflows) land in subsequent releases. The full implementation specification lives in `docs/agents/workflow.md` -- this Phase 1 surface matches §5 of that spec.

### Changed

- CI wheel-repair (`scripts/manage.py wheel_repair`) now uses cibuildwheel's per-build Python uniformly across Linux/macOS/Windows: each repair tool (`auditwheel`, `delocate-wheel`, `delvewheel`) is `pip install`-ed into `sys.executable` and invoked via its entry-point script resolved through `sysconfig.get_path("scripts")`. Previously Linux/macOS shelled out to `uvx` (which isn't preinstalled on the Windows runner) and the Windows path called `uvx delvewheel` and silently broke. The macOS Vulkan path additionally installs `wheel` because `do_fix_macos_vulkan_wheel` repacks the wheel via `python -m wheel pack` and cibw's venv doesn't ship it.

- `build-gpu-wheels-abi3.yml`: the `smoke` job (which fanned out to `_gpu-smoke.yml` across all GPU runners) is commented out for now while the per-backend wheel jobs are being stabilised. The `collect` and `upload_release` jobs continue to depend on the build jobs only.

- `ReActAgent` action parser now accepts namespaced tool names. The regex at `src/inferna/agents/react.py:_parse_action` was relaxed from `r"(\w+)\s*\((.*)\)\s*$"` to `r"([\w./\-]+)\s*\((.*)\)\s*$"`, and the tool-name validator was rewritten from a single `tool_name.isidentifier()` call to per-segment validation: split the captured name on `[./\-]` and require each non-empty segment to be a valid identifier. Permits MCP-namespaced tools (the `f"{server_name}/{tool_name}"` format that `src/inferna/agents/mcp.py:83` produces), dotted names like `module.helper`, and hyphenated names, while still rejecting `123abc`, empty names, and `()`. Previously every MCP-discovered tool routed through `ReActAgent._parse_action` failed with "Invalid tool name" the moment a `/` appeared.

- `ContractAgent` runtime context migrated from `threading.local` to `contextvars.ContextVar`. `_contract_context` in `src/inferna/agents/contract.py` is now a `ContextVar[Optional[ContractContext]]` with `default=None`; the `_get_current_context` / `_set_current_context` accessor signatures are unchanged, so no callsite edits were needed. The behaviour difference matters specifically for async tools: `threading.local` would have silently lost the active contract policy the moment execution hopped to a different thread (via `asyncio.to_thread`, `run_in_executor`, or any explicit thread-pool fan-out), at which point `contract_assert()` would fall back to the default ENFORCE policy regardless of what the surrounding agent had configured. `ContextVar` propagates through `asyncio` Task creation and `copy_context()` so the policy now follows the work.

- Grammar cache key now includes a fingerprint of tool parameter schemas. `src/inferna/agents/grammar.py` adds `_tools_fingerprint(tools)` which SHA-1s a sorted list of `(name, description, json.dumps(parameters, sort_keys=True, default=str))` triples and truncates to 16 hex chars. `get_cached_tool_grammar` and `get_cached_answer_or_tool_grammar` key on the fingerprint instead of `','.join(sorted([t.name for t in tools]))`. Previously, editing a tool's parameter list -- renaming a kwarg, tightening a type from `int` to `Literal["small", "large"]`, adding a required field -- would silently return a stale grammar from the cache because the tool *name* hadn't changed. The cache now invalidates on any structural change to a tool's schema.

- `ReActAgent._extract_thought` regex rewritten so multi-line Thought blocks are preserved end-to-end. The old pattern was `r"Thought:\s*(.+?)(?:\n|$)"` with `re.DOTALL` set, which is broken in a non-obvious way: the lazy `.+?` quantifier with a `\n`-or-end alternation in the trailing group means the match terminates at the first newline regardless of DOTALL. Replaced with a lookahead-terminated pattern: `r"Thought:\s*(.+?)(?=\n\s*(?:Action|Answer|Observation)\s*:|\Z)"` -- DOTALL still set, capture group runs greedy-bounded up to the next ReAct keyword or end-of-string. Chain-of-thought reasoning that spans multiple lines now reaches the prompt-truncation logic with all of its content intact.

- `_safe_get_type_hints` in `src/inferna/agents/tools.py` now calls `get_type_hints(func, include_extras=True)`. Without `include_extras=True`, PEP-593 `Annotated[T, ...]` metadata is stripped silently before reaching schema generation -- so any constraint markers attached at the call site (`Annotated[int, Ge(1)]`) would vanish before they could be read. This is a prerequisite for the new constraint-marker support listed under Added; the change is otherwise invisible to existing tools that don't use `Annotated[]`.

- ContractAgent module docstring (`src/inferna/agents/contract.py`) reframed around what schema cannot express. The earlier prose led with `@pre(lambda args: args['count'] > 0, "count must be positive")` -- an arg-validation pattern that `coerce_args` and `Annotated[int, Ge(1)]` now subsume entirely, making contracts look redundant for the documented use case. The rewrite leads with four niches that have no schema substitute (cross-field rules like `end > start`, state-dependent rules like `db.is_connected()`, behavioural postconditions like `r == sorted(r)`, and cross-iteration invariants like `s.errors < 3`), and redirects the redundant arg-validation pattern to the `Annotated[]` markers exported from `tools.py`. The `@pre` and `@post` decorator docstrings get the same treatment -- `@pre` is positioned as "non-schema preconditions only" with cross-field and state-dependent examples, `@post` keeps its examples but explicitly says it receives the *raw* return value (not its string render). Anti-pattern callouts steer users away from `@pre(lambda args: args['mode'] in {"a","b"})` (use `Literal["a","b"]`) and `@pre(lambda args: re.match(..., args['name']))` (use `Annotated[str, Pattern(...)]`). Zero code changes -- this is the doc reframe that makes the existing capability legible.

- Behaviour-shaping defaults for the two new fields on the `Tool` dataclass: `coerce` defaults to True (so the LLM's stringly-typed args land typed without per-tool opt-in) while `timeout` defaults to None (so existing tools aren't suddenly killed by a default budget). Both are settable via `@tool(coerce=..., timeout=...)` or by writing the field directly. The asymmetry is deliberate: coercion catches a class of crash the model frequently causes (and the cost of a wrong cast is a clean `ToolArgumentError` rather than a `TypeError` inside the tool body, so the false-positive cost is low); timeouts require the user to understand the tradeoff (a daemon thread that keeps running is the cost, and no value short of "the tool genuinely hangs" justifies it).

### Added

- `GenerationConfig` (`src/inferna/api.py`) gained thirteen sampler knobs that were previously bound at the C++ layer but unreachable from the high-level API: `frequency_penalty` (default 0.0, disabled), `presence_penalty` (default 0.0, disabled), `penalty_last_n` (default 64; -1 = full context, 0 = disabled), `mirostat` (default 0; 0 = off, 1 = v1, 2 = v2), `mirostat_tau` (default 5.0), `mirostat_eta` (default 0.1), `typical_p` (default 1.0, disabled — locally-typical sampling), `typical_min_keep` (default 1), `xtc_probability` (default 0.0, disabled — "Exclude Top Choices"), `xtc_threshold` (default 0.1), `dynatemp_range` (default 0.0, disabled — dynamic temperature; > 0 swaps `add_temp` for `add_temp_ext`), `dynatemp_exponent` (default 1.0), and `logit_bias` (default None — OpenAI-shape `Dict[int, float]` of token-id-to-bias). In probabilistic mode (`temperature > 0`, `mirostat == 0`), the new knobs slot into the existing `min_p -> top_k -> top_p` ordering at upstream-compatible positions: `typical_p` between `top_k` and `top_p` (skipped when `typical_p >= 1.0`), `xtc` after `top_p` (skipped when `xtc_probability == 0.0`), and `add_temp_ext` replaces `add_temp` when `dynatemp_range > 0` (otherwise plain `add_temp`). Existing `min_p`/`top_k`/`top_p` order is preserved for behavioural compat — upstream uses `top_k -> typical_p -> top_p -> min_p`, but reordering would silently change sampling output for current users. Same chain logic mirrored across the three sampler-build sites: `LLM._create_sampler` (`src/inferna/api.py`), `BatchGenerator.generate_batch` (`src/inferna/batching.py`), and `Chat.__init__` (`src/inferna/llama/chat.py`) — the last of which previously hardcoded `add_penalties(64, repeat_penalty, 0.0, 0.0)` and now honours the new kwargs. - Whisper streaming transcription (`inferna.whisper.streaming.WhisperStreamer` and the iterator helper `transcribe_stream`). whisper.cpp's encoder consumes a full mel spectrogram per call -- there is no native incremental decoder -- so the streamer implements the standard rolling-window re-pass pattern from upstream's `examples/stream`: callers `feed(samples)` chunks of mono float32 16 kHz audio (any chunk size); the streamer buffers up to `length_ms` of audio (default 10s) and runs `whisper_full` over the rolling window every `step_ms` of newly-accumulated audio (default 3s, matching the upstream default). Each pass emits `StreamSegment(text, t0, t1, is_final)` records in stream-relative time. `is_final=True` marks segments whose audio has rolled past the trailing edge (next pass's window won't see them, so their text is committed); `is_final=False` marks the in-flight tail that may be revised by subsequent passes. A monotonic watermark (`_final_until_sec`) suppresses re-emission of regions already committed -- the same audio region is never finalised twice. `flush()` runs a final pass that marks all remaining segments final and closes the streamer. `transcribe_stream(audio_iter, ...)` wraps the class for the common iterator-of-chunks shape (file readers, mic callback queues). Validation: `length_ms < step_ms` raises `ValueError`; non-float32 / non-1-D input is auto-coerced via `np.asarray`. Tests: 10 in `tests/test_whisper_streaming.py` covering arg validation, silence handling (no false-positive transcripts on pure-zero audio), JFK end-to-end (canonical phrase fragments present in the joined finals after chunked feed), iterator helper parity, monotonic non-overlapping finals, post-close `feed()` raises, and context-manager close. Wall-clock: 4.2s for the full file using the bundled `models/ggml-base.en.bin` and `tests/samples/jfk.wav`. Module-level `np` import (numpy is a project dep declared in `pyproject.toml`); `np = self._np` lazy-stash pattern dropped after a build/typecheck pass surfaced the unnecessary `Any`-leak.

- `LLM` now caches the seq-0 KV state across calls and reuses the prefix when a follow-up prompt overlaps the previous (prompt + generated) turn. Implementation: every successful call updates `self._kv_seq_tokens` (a list of token ids reflecting whatever currently lives in the live context's seq 0 — prompt followed by everything we sampled). On the next call, `_generate_stream` computes the longest token-id prefix shared with the new prompt, drops the divergent tail via `ctx.memory_seq_rm(0, overlap, -1)`, and prefills only the suffix. The last prompt token is always reserved for fresh decode so `sample(ctx, -1)` reads up-to-date logits, even when the new prompt is exactly the cached prompt. Cache hits are correctness-preserving (replay of the same KV positions) so determinism under a fixed seed is identical to a full prefill — verified by a regression test in `tests/test_prompt_cache.py`. Measured speedup on a 200-token prefix with 10 generated tokens: **8.2×** vs. cold-start prefill on the default Llama-3.2-1B test model. - `LLM._generate_stream` (`src/inferna/api.py`) and `BatchGenerator.generate_batch` (`src/inferna/batching.py`) no longer corrupt multibyte UTF-8 codepoints that span token boundaries. The previous `vocab.token_to_piece(...)` path used `PyUnicode_DecodeUTF8(..., "replace")` inside the C++ binding, so a token containing a partial UTF-8 sequence (lone lead byte or continuation byte — routine output of byte-level BPE) was silently turned into `U+FFFD` replacement characters at the seam, even though the bytes from the next token would have completed the codepoint. The `except UnicodeDecodeError` arms were dead code under that decoder. Stop-sequence matching now operates on the true decoded text rather than `U+FFFD`-poisoned strings, fixing a related miss where a stop string straddling two tokens could fail to trigger.

- `LLM._apply_template` (`src/inferna/api.py:1334`) and `Chat._apply_template` (`src/inferna/llama/chat.py:131`) no longer mask real bugs in the vendored Jinja path. The bare arm is now narrowed to `(TypeError, KeyError, AttributeError)` (the realistic render-context failures: missing variable, wrong type in messages, attribute lookup on `None`) and emits `logger.warning("Jinja chat-template rendering failed (%s); falling back to C-API path", type(exc).__name__)` so the degradation is observable rather than silent. Other exception classes propagate, surfacing genuine bugs at the source instead of routing them through a fallback that may silently produce different output.

- `BatchMemoryPool.get_batch` (`src/inferna/llama/_python_helpers.py:107`) no longer hands out half-reset batches when `batch.reset()` raises. The previous `try: batch.reset(); except Exception: pass` returned the same pooled batch even when reset failed, leaving the caller with a `LlamaBatch` in an undefined state — possibly with stale tokens, sequence ids, or logits flags from the prior request. The exception path now logs a `logger.warning` (`type(exc).__name__: str(exc)`) and falls through to constructing a fresh `_N.LlamaBatch(n_tokens=..., embd=..., n_seq_max=...)`, which is the same construction the empty-pool branch uses. - `EmbeddedServer` slot reuse no longer fails with `decode: failed to initialize batch` after the first request. `ServerSlot.reset()` previously zeroed `context.n_tokens` but did not clear the underlying llama KV cache, so the second request — starting a new decode at position 0 while the cache still held positions `0..N-1` from the prior run — tripped llama's "sequence positions must remain consecutive" guard. `reset()` now calls `self.context.kv_cache_clear()` before zeroing `n_tokens`, which releases all cells across all sequences and is the correct slot-reuse semantics. Affects both streaming and non-streaming paths; verified across mixed orderings (non-stream → stream, stream → non-stream, repeated stream).

- `inferna_mg_http_reply_bytes` (`src/inferna/llama/server/mongoose_wrapper.c`) no longer emits an empty `Content-Length` header. Mongoose's `mg_printf` ships its own format-specifier subset that does **not** support `%zu`; passing `body_len` (`size_t`) through `%zu` produced `Content-Length: ` (empty value), which curl rejects with `Invalid Content-Length` and Chrome treats as a 0-byte body. urllib silently fell back to read-until-EOF, so the bug went undetected through Phases 1–3 testing. Cast to `unsigned long long` and use `%llu`, which mongoose does support.

- `src/inferna/llama/server/__main__.py` no longer fails to start the embedded server with `ImportError`. The CLI imported `from .mongoose_server import EmbeddedServer`, but no such module exists — the actual class lives in `.embedded`. The import path was stale from a pre-rename of the file. Fixed.

- `EmbeddedServer.start()` now releases all native state when bring-up fails. Previously, if `_mgr.listen()` returned False (or any later step raised), the server retained `_model` / `_slots` / `_embedder`, the manager's `_dispatch` closure, and the `signal.signal()` handlers — pinning the entire instance (and its `LlamaModel` + `LlamaContext` + `LlamaSampler` chain) to interpreter shutdown. That late teardown ran after Metal cleanup, tripping `GGML_ASSERT([rsets->data count] == 0)` and aborting the process. The cleanup is now a single `try`/`finally` keyed on a `success` flag: any non-success path drops the dispatcher handler, restores signal handlers, and clears refs to the loaded model/slots/embedder. Regression test: `tests/test_mserver_embedded.py::TestEmbeddedServerLifecycle::test_failed_start_releases_native_state`.

- SD preview callback no longer hands Python use-after-free wrappers. The C trampoline (`_c_preview_cb` in `_sd_native.cpp`) previously wrapped each `sd_image_t` with `owns=false`, retaining a raw pointer into the sd.cpp-owned buffer that gets reused or freed on the next sampling step. Any frame the Python callback stashed past the callback's return read poisoned/freed memory. Each frame is now deep-copied into a wrapper-owned buffer (`std::malloc`/`std::memcpy`, `owns=true`), matching the allocator convention used by `SDImage.from_numpy`. Regression test added in `tests/test_sd.py::TestPreviewCallback::test_preview_callback_frame_data_survives_callback_return`, backed by a new test-only `_test_invoke_preview_cb` binding that synthesizes a preview event and overwrites/frees the source buffer before returning.

- `Speculative.is_compat` no longer clobbers the target context's KV cache. The probe previously decoded two dummy tokens into seq 0 and then called `kv_cache_clear(True)`, silently destroying any prefill the caller had built. The probe now picks the first empty sequence id in `[0, n_seq_max)` and removes only that probe seq when finished, leaving caller data intact. When every sequence is occupied (typical for default `n_seq_max=1` with seq 0 prefilled), `is_compat` raises `RuntimeError` with an explanatory message rather than corrupting state. Two regression tests added in `tests/test_speculative.py`.

### Changed

- `LlamaVocab.tokenize()` now honors llama.cpp's negative-return contract: if the initial buffer is too small, it resizes to the required capacity (`-rc`) and retries once. Previously it capped the buffer at `min(text.size()*2 + 100, n_vocab)` — a nonsensical cap that produced spurious tokenization failures on long inputs and small-vocab models.

- `LlamaVocab.token_to_piece()` now decodes piece bytes with `errors="replace"` (via `PyUnicode_DecodeUTF8`). Byte-level BPE pieces frequently include partial UTF-8 sequences; the previous strict decode could raise `UnicodeDecodeError` from inside the hot generation loop on multilingual models. Callers continue to receive `str`.

- `_llama_progress_cb` now returns `false` (abort the load) when the user-supplied progress callback raises. Previously it returned `true`, so a `KeyboardInterrupt` or any handler exception was silently ignored and loading continued. This honors llama.cpp's "return false to abort" contract.

- Log/progress/preview callbacks across `_llama_native` and `_sd_native` now acquire the GIL *before* checking `is_valid()` / `is_none()` on the global callback handle. The prior pattern raced with `set_*_callback`, which mutates the `nb::object` under the GIL and could corrupt the handle on the worker thread.

- `MtmdContext.get_output_embeddings()` now returns a flat row-major `list[float]` of size `n_tokens * n_embd` (matching `LlamaContext.get_logits()`) rather than `list[list[float]]`. Removes ~2.4M `PyFloat` allocations per call for typical CLIP shapes (`n_tokens=576, n_embd=4096`).

- `SDContext.__exit__` now calls `self.close()` for deterministic teardown of the native context (and its GPU buffers) at `with`-block exit. Previously it was a no-op and the context lingered until GC, which on macOS Metal accumulated working-set pressure across consecutive contexts.

- `LlamaModelKvOverride.key` / `.val_str` setters now raise `invalid_argument` when the input exceeds the underlying fixed-size char buffer instead of silently truncating via `strncpy`. A truncated key would surface later as a confusing "key not found" failure; the new behavior reports the actual length and the limit.

- `LlamaVocab.detokenize` error message: previously labeled the return code as `text="..."` (e.g. `text="-1"`) due to a mistakenly-swapped pair of formatters. Now reads `rc=-1 n_tokens=N`, which is what was always meant.

- `Makefile` `make test-cli` / `test-chat` / `test-tts` / `test-server` invoked `python -m inferna.<subcommand>` (which is not a valid module path — the actual modules live under `inferna.llama.*`). Switched to the unified CLI entry point: `python -m inferna <subcommand>`.

- `.github/workflows/build-gpu-wheels.yml` and `build-gpu-wheels-abi3.yml` had two top-level `env:` blocks each. YAML semantics let the second block silently shadow the first, so the `CIBW_VERSION` variable lifted in for C4 was undefined for the rest of each workflow. Merged into a single `env:` block per file so `${{ env.CIBW_VERSION }}` resolves correctly.

- `LlamaModel.lora_adapter_init()` now raises `FileNotFoundError` (with a helpful message) when the LoRA path does not exist, instead of throwing `nb::python_error()` with no Python exception set.

- `set_preview_callback()` in `inferna.sd.stable_diffusion` now logs a warning when a user callback raises, matching the behavior of the progress and log callbacks. Previously the exception was silently swallowed.

- `MACOSX_DEPLOYMENT_TARGET` is now consistently `11.0` across `Makefile`, `scripts/manage.py` (both the module-level default and `WheelBuilder.get_min_osx_ver`), and `pyproject.toml`'s cibuildwheel macOS section. Previously the four sites carried `14.7` / `12.6` / `10.9`-or-`11.0` / `11.0`, producing wheels with mismatched `LC_BUILD_VERSION` minimums depending on which build path was taken.

Without this, a local `make wheel-cuda` on a Metal-built tree would silently produce a wheel claiming CUDA support but linking Metal-built archives. cibuildwheel's `before-build` hook already handled this in CI; local make did not.

Behavior is consistent with the other three context types.

- `manage.py` no longer silently uses a stale source checkout when the requested version changes. Each `build()` entry point (llama.cpp static + dynamic, whisper.cpp, stable-diffusion.cpp, sqlite-vector) calls a new `verify_checkout()` helper that compares `git rev-parse HEAD` against `git rev-parse <self.version>` and aborts with a clear "run `make reset`" message on mismatch. Previously the guard was `if not src_dir.exists(): self.setup()`, which meant a partial checkout from a prior run would silently take precedence over the new version pin.

- `_mg.send_reply()` (the unvalidated module-level reply primitive) accepted any `uintptr_t` and dereferenced it directly. A stale connection id (kept past request scope) or a fabricated value would trigger undefined behavior on freed memory. Replaced by `Manager.send_reply()` which walks `mgr.conns` and rejects pointers not in the live list (and pointers whose connections are mid-close).

- `EmbeddedServer.stop()` now restores the SIGINT/SIGTERM handlers it installed in `_setup_signal_handlers()`. Previously the bound `self._signal_handler` method registered with `signal.signal()` retained a strong reference to the EmbeddedServer, which retained the `_mg.Manager`, `LlamaModel`, every slot's `LlamaContext` + `LlamaSampler`, and any embedder model — all the way to interpreter shutdown. On macOS this tripped a `GGML_ASSERT([rsets->data count] == 0)` in `ggml_metal_free` because the Metal device deallocated while LlamaContexts were still alive. New regression test `TestEmbeddedServerNoSignalRetention.test_server_released_after_stop` pins the fix using `weakref.ref(server)` after `stop() + del + gc.collect()`.

- `make qa` now passes cleanly. Fixed a real runtime regression in `inferna/llama/llama_cpp.py` — a previous `ruff --fix` had stripped the `from ._python_helpers import (...)` and `from ._speculative import (...)` re-exports thinking they were unused, breaking `import inferna` at module load (`batching.py` imports `get_pooled_batch` / `return_batch_to_pool` through the `llama_cpp` facade). Restored the imports using the explicit `X as X` re-export form so static analyzers and linters recognize them as intentional. Plus 117 mypy strict-mode errors across 6 files: type annotations added to `_python_helpers.py` (helpers, n-gram cache, download API), `embedded.py` (signal-handler types, `__enter__`/`__exit__` signatures, dict generics), `stable_diffusion.py` (SDImage proxies, tuple-pair properties, callback wrappers); ruff E701/E702 (one-statement-per-line) fixes in `stable_diffusion.py` `save()` and `SDContextParams.__init__`; mypy override added for the nanobind-subclassing modules to relax the four strict-mode checks that fire purely because nanobind classes are seen as `Any`.
